# Function and variable reference

Every function and variable named in the kit's Ghidra markup for stock V137.4.5, with what it does. The same
text appears in Ghidra as plate comments once [`tools/ghidra_setup.py`](../tools/ghidra_setup.py) has applied
the markup. Addresses are Ghidra global addresses (see [the firmware map](firmware-map.md)): flash `7Fxxxx`, RAM
`0FExxx` (RAM `0x2350` is `0FE350`), I/O registers below `000800`. Summaries starting "Likely:" are inferred, not
established.

Generated from `markup/functions.tsv` and `markup/labels.tsv` by `tools/gen_reference.py`; edit those, not this file.


## ISR

| Address | Function | What it does |
|---|---|---|
| `7F4BC9` | `ISR_SCI0_rx` | SCI0 receive interrupt: when a byte has arrived, passes it to sci_rx_handler.<br><br>Tests the receive-data-full flag in the SCI0 status register and reads the data register. |
| `7F4BDA` | `ISR_CAN1_rx` | CAN1 receive interrupt: accepts register-read requests on 18EF70xx from any source and arms the reply.<br><br>Builds the received ID and matches it against 0x18EF7000 under mask 0x1FFFFF00 (priority 6, PGN 0xEF00, destination 0x70). It keeps the sender's source address for the reply.<br>Data bytes 0-1 are the start register and bytes 2-3 the count. The start becomes an index into a 40-register table based at 0x1388 (starts of 0x1402 and above are first shifted down by 0x5B), and index + count may not exceed 40; anything else is ignored before any state changes.<br>A request is taken only while the busy flag 0x26DF is clear. It sets busy and the poll-seen flag 0x26E0 (used by alarm_cellOV_eval), and can_settings_multiframe_tx sends the reply.<br>Patched by the rvc_status recipe: the busy test is spliced to a dispatcher that also accepts the manual-heater (AA 55) and alarm-mask (4D 53) lease commands, DLC 8, in system states 3 and 4, and requests the 18FF7070 status acknowledgement. |
| `7F4D47` | `ISR_CAN4_rx_commands` | CAN4 receive interrupt: decodes the ID and handles the BMS commands, only while g_sys_state is 3 or 4.<br><br>0x011 "UA": endless loop, so the COP watchdog resets into the bootloader. Extended 0x08F62DE2 "UA": the same.<br>0x100: balancing enable, threshold and reference, and d3 into g_work_mode.<br>0x20F AA AA: SoC = d2, overwritten on the next soc_calc2 pass.<br>0x300: copied to g_msg300_data; a valid checksum with d0 bit2 set resets all 11 alarm objects.<br>0x310-0x313: copied to g_msg310..313_data; 0x311 sets SoC = d5 when the last 0x300 had d0 bit0 set.<br>0x410-0x41A: settings frames into g_settings_frame410..41A, live at once, saved only when all 11 arrive.<br>0x500 AA AA: d2 = 01 sets the telemetry table's enable bit, d2 = 02 starts the 0x450-0x45A settings dump.<br>Extended 0x999: stores d0-d7 into g_cmd999_*, which nothing reads. This is a dead debug command.<br>Patched by the rvc_status recipe: a smaller equivalent ID decoder frees room for the heater helpers, and the 0x999 case does nothing.<br>Patched by the uvcharge recipe: the 0x100 work-mode byte is ignored while either UV L3 countdown runs. |
| `7F55F6` | `ISR_CAN0_rx` | CAN0 receive interrupt: would copy frame 0x18FF50E5 to RAM 0x2718, but CAN0 is never initialized, so it never runs.<br><br>Reads its controller base from RAM 0x2620, which nothing writes. On a match it sets bit3 of RAM 0x2624 and copies the 8 data bytes. |

## can

| Address | Function | What it does |
|---|---|---|
| `7F8B95` | `can_tx` | Generic MSCAN transmit: sends one frame on the controller given, standard or extended, if a transmit buffer is free.<br><br>Arguments: DLC in B; on the stack, the data pointer, ID high word, ID low word and controller register base. An ID high word of 0 selects a standard frame.<br>Picks the lowest free buffer through can_txbuf_free, packs IDR0-IDR3, copies the data and queues the frame. Returns B = 1 when sent, 0 when no buffer was free. The caller removes the arguments.<br>Six of its seven call sites use CAN4. The only CAN1 caller is can_settings_multiframe_tx. |
| `7F8C6B` | `can_txbuf_free` | Helper for can_tx: returns the controller's transmit-buffer-empty flags (zero when all three buffers are busy). |
| `7FAC93` | `can_settings_multiframe_tx` | Every main-loop pass: sends the reply to a pending CAN1 register request, up to 4 words per frame, one frame per 50 ms tick.<br><br>Reads the register mirror at 0x23AE, sends on 18EFxx70 (xx = the requester) through can_tx with the CAN1 base (its only CAN1 transmitter), advances the index and the remaining count (0x26E4), and clears the pacing flag 0x26E1.<br>Stock bug: when the final frame carries exactly 4 words, busy (0x26DF) stays set until the next pass, so a poll that arrives about 1.3 ms later is dropped. The APS-500 then often misses 1392 and 1395.<br>Patched by the rvc_status recipe: busy is released with the final frame, and while an alarm-mask lease runs the copies of 1392 and 1393 are ANDed with EB3E and FEFF.<br>Patched by the uvcharge recipe: the lease mask on 1392 becomes EB16, which also hides the two difference L1 bits. |
| `7FAE19` | `can_tx_table_init` | At boot: builds the CAN4 transmit tables: the 0x450-0x45A settings dump and the periodic telemetry frames.<br><br>The settings-dump table (11 entries, header g_flag_cmd500_02) starts disabled.<br>The telemetry table (header g_flag_cmd500_01) is enabled. It holds 0x501 onward, the cell frames 0x510+ (one per four cells, from the cell count) and the temperature frames 0x550+ (from the probe count). |
| `7FB2C8` | `can_periodic_tx_scheduler` | Every main-loop pass: sends the CAN4 frames: telemetry, the settings dump, the 0x401 ack and 0x7FE.<br><br>Sends 0x401 (AA AA, the settings-save acknowledgement) when bit0 of 0x28DE is set, and 0x7FE on its flag. It then sends pending entries while a CAN4 transmit buffer is free.<br>Builds the payloads. 0x501: the current float and SoC. 0x504: alarm bits, d4 = g_war_max_level, d5 = g_war_count, d6 = relay byte (g_tx504_relay_byte). Other frames carry cells, temperatures, the negated 1390 limit and the 0x450+ settings.<br>Every can_tx call here uses the CAN4 base. |
